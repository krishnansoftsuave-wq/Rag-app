## 2. Diagnosis from the trace (one hop)

The trace's `context_ids` start with `novacloud_sdk_v2_archived#0`. **Retrieval served the archived 2.x page**, and the model copied its `NovaClient.connect` / `put_object` sample next to the correct 3.x one. The model didn't write it from memory: the deprecated calls appear word for word in the retrieved chunk.

## 3. Failure → test: RED, then GREEN

**Eval case:** `backend/tests/evals/deprecated_method_cases.json`, loaded by the Week-6 suite `backend/tests/unit/test_novacloud.py`.

| Case | What it checks |
|---|---|
| `W11-DEPRECATED-1` | "Show me Python code to upload a file…": the answer must contain `objects.upload`, and its code blocks must not call `put_object` or `NovaClient.connect`. |
| `W11-LEGACY-V2` | "We are pinned to novacloud-sdk 2.x…": the answer **must** still contain `put_object`. This guards against the fix breaking legacy support. |

**Run:** `python tests/unit/test_novacloud.py --suite drill --label red|green`.

The drill suite is 5 questions: Q1, Q7 and Q12 from the 20-case suite as regression guards, plus the 2 new cases. That keeps each run inside the free-tier token limit.

| Run | Prompt / retrieval | Result | Output |
|---|---|---|---|
| **RED** (before fix) | `rag-v1.0`, archived docs searched | **4/5**: W11-DEPRECATED-1 FAIL (code uses `put_object`, `NovaClient.connect`) | `backend/results/week11/suite_red.txt` |
| Attempt 1 (prompt only) | `rag-v1.1`, archived docs searched | **4/5**: still FAIL, the model added an "if you are on 2.x" sample | `backend/results/week11/suite_green_attempt1_prompt_only.txt` |
| **GREEN** (after fix) | `rag-v1.1` + `exclude-archived-v1` | **5/5**: all pass, legacy case included | `backend/results/week11/suite_green.txt` |

**Honesty note on the check:** it was tightened twice after the RED run, both times to match the complaint ("a code sample *using* a deprecated method"), not to make a run pass:
1. From "the answer never mentions `put_object`" to "no code block contains it". Naming the old method in a migration table is correct behaviour.
2. Then code comments were excluded. `# NovaClient.connect() was removed, use Client()` warns about the method; it doesn't call it.

Every saved run was re-scored under the final rule with `--rescore`, and the RED run still fails 4/5 (`backend/results/week11/rescore_red.txt`). The final GREEN 5/5 is a fresh live run with the final rule.

## 4. The fix, the version bump, canary and rollback

**Fix:**
- **Prompt layer.** `PROMPT_VERSION` was bumped from `rag-v1.0` to **`rag-v1.1`** (`backend/app/services/llm/prompts.py`, changelog in the docstring). Both prompts now say: code for the current version only, unless the user says they're on an older version.
- **Retrieval layer.** Docs can be marked `archived` (`scripts/set_doc_status.py`). Archived docs are left out of retrieval unless the user's *question* asks about an older version (`backend/app/services/retrieval/version_policy.py`). The policy name `exclude-archived-v1` and the excluded doc ids are logged on every retrieval span.

**Canary:** route 10% of `/chat` traffic to `rag-v1.1` + `exclude-archived-v1` for 24 hours. Then:
- `find_trace.py --prompt-version rag-v1.1 --code-only --text "put_object|NovaClient\.connect" --in answer` must return 0.
- p95 cost and latency must stay within 10% of `rag-v1.0`.

**Rollback:** if a deprecated call shows up in a v1.1 code sample, a 2.x user reports losing legacy answers, or p95 cost or latency rises more than 20%:
- revert `PROMPT_VERSION` to `rag-v1.0`
- run `set_doc_status.py <doc> current` on the archived docs

Both are config-only, with no re-index. The traffic split itself is not built yet; today the switch is all-or-nothing.
